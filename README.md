# Yerel Apache Airflow Bu depo, Apache Airflow'u Docker Compose ile yerel geliştirme ve öğrenme amacıyla çalıştırır. `LocalExecutor` görevleri Airflow ortamında yerel olarak yürütür; Celery worker ve Redis servisi kullanılmaz. PostgreSQL Airflow metadata'sını saklar, DAG dosyaları `dags/` klasöründen okunur ve web arayüzü `http://localhost:8080` adresinde açılır. > Bu kurulum yerel geliştirme içindir; internete açık üretim ortamı olarak tasarlanmamıştır. ## RAM kullanımı Bu Compose düzeninde Celery worker ve Redis olmadığından, Celery/Redis tabanlı bir düzene göre daha az servis çalışır ve kaynak tüketimi azalabilir. Bu bir sabit RAM sınırı değildir: Airflow API server, scheduler, DAG processor, triggerer ve PostgreSQL yine çalışır; görevlerin bellek kullanımı ve paralelliği toplam tüketime etki eder. Docker Desktop kaynaklarını bilgisayarınıza uygun ayarlayın ve kullanımı görmek için `docker stats` çalıştırın. ## Gereksinimler - Git - Docker Desktop kurulu ve çalışır durumda olmalı; Windows'ta Linux konteynerlerini çalıştırabilmeli. - GitHub deposuna erişim (özel depolar için GitHub kimlik doğrulaması gerekir). ## GitHub'dan indirip ilk kez çalıştırma Komutları PowerShell'de sırayla çalıştırın. `GITHUB_KLON_ADRESI` yerine GitHub'daki **Code → HTTPS** menüsünden aldığınız adresi yazın. `REPO_KLASORU` yerine `git clone` komutunun oluşturduğu klasör adını kullanın. ### 1. Depoyu klonlayıp VS Code'da açın ```powershell git clone GITHUB_KLON_ADRESI Set-Location .\REPO_KLASORU code . ``` Alternatif olarak **Code → Download ZIP** ile indirin, ZIP'i çıkarın ve `docker-compose.yaml` bulunan klasörü VS Code ile açın. ### 2. Yerel `.env` dosyasını oluşturun `.env`, `docker-compose.yaml` ile aynı proje kökünde bulunmalı ve GitHub'a yüklenmemelidir. Fernet anahtarı oluşturmak için aşağıdaki komut imajı gerekirse Docker Hub'dan çeker ve anahtarı terminale yazdırır: ```powershell docker run --rm apache/airflow:3.3.2 python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())" ``` Çıktıdaki anahtarı kullanarak proje kökünde `.env` dosyası oluşturun. Eşittir işaretlerinin çevresine boşluk koymayın: ```env AIRFLOW_UID=50000 FERNET_KEY=BURAYA_URETILEN_ANAHTAR ``` `BURAYA_URETILEN_ANAHTAR` metnini gerçek üretilen değerle değiştirin. Fernet anahtarını paylaşmayın veya depoya eklemeyin. Bu repodaki `.gitignore`, `.env` dosyasını hariç tutar. Daha önce kullanılan bir anahtarı değiştiriyorsanız, Airflow veritabanında o anahtarla şifrelenmiş bağlantı parolaları bulunabilir; anahtarı gelişigüzel değiştirmeyin. Anahtar GitHub'a veya başka bir yere açığa çıktıysa önce veritabanını yedekleyin ve Airflow'un anahtar döndürme yöntemini uygulayın. ### 3. `.env` dosyasının Git tarafından izlenmediğini kontrol edin ```powershell git check-ignore .env git status --short ``` İlk komut `.env` yolunu göstermeli; `.env` `git status` çıktısında commit edilecek dosya olarak görünmemelidir. Dosya daha önce Git'e eklenmişse `.gitignore` tek başına izlemeyi durdurmaz. Böyle bir durumda: ```powershell git rm --cached .env ``` Bu komut dosyayı bilgisayardan silmez, sadece Git takibinden çıkarır. Eğer gizli değer daha önce GitHub'a gönderildiyse, anahtarın açığa çıktığını varsayın ve doğru anahtar döndürme adımlarını uygulayın. ### 4. Compose yapılandırmasını doğrulayın ```powershell docker compose config --quiet ``` Komut hatasız biterse devam edin. Hata verirse `docker-compose.yaml` ve `.env` dosyalarının aynı proje kökünde olduğunu, `.env` değişkenlerinin doğru yazıldığını kontrol edin. ### 5. Airflow servislerini başlatın ```powershell docker compose up --pull always -d ``` İlk çalıştırmada Docker imajları indirilebilir ve servislerin sağlıklı duruma gelmesi biraz zaman alabilir. ### 6. Servisleri ve DAG dosyasını doğrulayın ```powershell docker compose ps docker compose exec airflow-dag-processor ls -la /opt/airflow/dags docker compose exec airflow-scheduler airflow dags list docker compose exec airflow-scheduler airflow dags list-import-errors ``` `dags/firstdag.py` konteyner içinde `/opt/airflow/dags/firstdag.py` olarak görünmeli; DAG listesinde `First_dag` bulunmalı. Hata yoksa tarayıcıda adresini açın. Bu yapılandırmada ilk yerel giriş bilgileri varsayılan olarak `airflow` / `airflow` şeklindedir; `docker-compose.yaml` içindeki kullanıcı/parola ortam değişkenleriyle değiştirilebilir. Örnek giriş bilgilerini internete açık sistemlerde kullanmayın. ## DAG ekleme ve sorun giderme Yeni Python DAG dosyalarını depo kökündeki `dags/` klasörüne ekleyin. Airflow dosyaları otomatik tarar; ardından UI'ı yenileyin. DAG bulunmuyorsa: 1. VS Code terminalinde `Get-Location` çalıştırarak `docker-compose.yaml` bulunan proje kökünde olduğunuzu doğrulayın. 2. `Get-ChildItem .\dags` ile DAG dosyasının host klasöründe olduğunu kontrol edin. 3. `docker compose exec airflow-dag-processor ls -la /opt/airflow/dags` ile aynı dosyanın konteynerde göründüğünü kontrol edin. 4. Windows'ta konteyner klasörü boşsa Docker Desktop dosya paylaşımı ayarlarında depo klasörüne erişim verin. Sonra şu komutu çalıştırıp yeniden kontrol edin: ```powershell docker compose up --pull always -d --force-recreate airflow-dag-processor docker compose exec airflow-dag-processor ls -la /opt/airflow/dags ``` 5. Import hatalarını inceleyin: ```powershell docker compose exec airflow-scheduler airflow dags list-import-errors docker compose logs --tail 100 airflow-dag-processor ``` ## Günlük kullanım PowerShell'de `docker-compose.yaml` bulunan proje klasöründe: ```powershell # Çalışan servislerin durumunu göster docker compose ps # Logları izle docker compose logs -f # Airflow scheduler ve DAG processor loglarını izle docker compose logs -f airflow-scheduler airflow-dag-processor # Servisleri durdur; PostgreSQL verisi kalıcı volume'de korunur docker compose down # Daha sonra tekrar başlat docker compose up --pull always -d ``` `docker compose down -v` PostgreSQL volume'ünü ve içindeki Airflow metadata'sını siler; sıfırlamak istemiyorsanız bu komutu kullanmayın. ## GitHub'a güncelleme gönderme Önce `git status --short` ile `.env` dosyasının listede olmadığını kontrol edin. Ardından: ```powershell git add README.md .gitignore docker-compose.yaml dags git commit -m "Document local Airflow setup" git push ``` DAG dosyalarına parola, token veya API anahtarı yazmayın. Gizli bilgileri GitHub'a yüklemeyin. ## Neler GitHub'a yüklenir, neler yerel kalır? GitHub deposunda Compose yapılandırması, README ve `dags/` içindeki DAG kodları bulunur. `.env` gizli ve makineye özel olduğu için her kullanıcı tarafından yerelde oluşturulur.
